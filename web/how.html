Architecture

Every interruption is a new epoch.

A session has one integer, the epoch. Everything the agent starts (plans, tool calls, outputs) is stamped with it. When you correct, change goal or cancel, the epoch moves on and everything older is cancelled or dropped.

The pipeline

What happens when you interrupt

  1. Classify in milliseconds. Deterministic rules label the utterance as a correction, goal change, addition, cancel, backchannel, hesitation or question. Only if they are unsure does an LLM decide, with a hard timeout and a rule-based fallback.
  2. Acknowledge instantly. A template reply (“Got it, switching to the 6pm flight…”) goes out in under 300 ms with no LLM call. It never says something is booked before it is.
  3. Bump the epoch for corrections, goal changes and cancels. Backchannels (“uh-huh”) and hesitations (“um…”) do not bump it and do not interrupt.
  4. Cancel the old epoch. Its tasks are cancelled; any result that still arrives with an old epoch is dropped and logged, never shown.
  5. Patch, don't restart. An immutable snapshot of slots and plan per epoch lets a correction change one field (time: 8pm → 6pm) and reuse still-valid speculative reads.
  6. Guard every write. It runs only if the plan is committed, the epoch is still current (checked again just before dispatch), and the idempotency ledger has not seen the same write.
  7. Compensate if it was too late. A write that committed and then went stale is undone through the same ledger (for example a booking is cancelled and refunded).

Design choices worth knowing

Never freezes

Every LLM call has a timeout and a deterministic fallback. With the mock LLM the whole system runs without Ollama.

Stale writes are visible

A write stopped by the fence is recorded as BLOCKED, distinct from a real FAILED, and can be retried later.

Everything is traced

Each component writes structured JSONL events with epochs and millisecond timestamps, rendered on the Timeline.
